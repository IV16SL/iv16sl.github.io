部署 OpenPGP Web Key Directory（WKD）教程

  以域名 huanjue.me 为例。把下面所有 you@huanjue.me 换成你自己的邮箱地址，把 you 换成邮箱的本地部分（@ 前面的部分）。

WKD 是什么

  WKD 让别人给你发加密邮件时，不用先去密钥服务器找你的公钥，也不用你手动把公钥发过去。发件方的客户端（例如 GnuPG、Thunderbird、支持 WKD 的网页邮箱）会直接向你的域名发 HTTPS 请求，把你的公钥拉回来。

  关键点：

  • 只发布公钥，永远不要发布私钥。
  • 全程 HTTPS，证书必须有效，自签名证书会被客户端拒绝。
  • 公钥文件是二进制格式，不带文件扩展名，不是 ASCII armored 文本。
  • 文件名不是邮箱明文，而是本地部分的 SHA-1 经过 z-base32 编码后的哈希，这样不会在 URL 里直接暴露邮箱的本地部分。

两种方法：高级方法和直接方法

  客户端会先试高级方法，失败再试直接方法。两者可以同时部署，互不冲突。

  区别：

  • 高级方法需要一个 openpgpkey.huanjue.me 子域名，可以把 WKD 放在和主站不同的服务器上，也能一个 WKD 服务托管多个域名。
  • 直接方法不需要额外 DNS，但要保证 openpgpkey.huanjue.me 这个子域名不存在；如果域名用了通配符解析，还要给 openpgpkey 加一条空 TXT 记录，防止客户端误判。

  本教程同时部署两种方法，覆盖面最大。

前置条件

  • 你已经有一对 OpenPGP 密钥，并且密钥上有一个 UID 就是你要发布的邮箱，例如 you@huanjue.me。
  • 密钥里有可用于加密的子密钥；只有签名没有加密子密钥的密钥，别人拿到了也加密不了。
  • 能控制 huanjue.me 的 DNS 和网站内容。
  • 服务器能通过 HTTPS 提供静态文件，证书有效。

用在线工具再验一遍

  命令行都通了之后，还可以用第三方在线验证工具从外网再查一次，相当于请别人从头走一遍客户端的发现流程。推荐用 Web Key Directory Validator：

  打开网站，输入你要验证的邮箱地址（例如 hi@huanjue.me），提交后它会按 OpenPGP Web Key Directory 的规范逐项检查：policy 文件能不能拿到、公钥能不能在高级方法和直接方法的路径上拉到、拉到的钥匙是不是二进制格式、UID 和要查的邮箱对不对得上、有没有可用的加密子密钥、钥匙有没有过期或被吊销。

  全部通过就是部署没问题；哪一项没过，就按那一项的名字回头查对应步骤：policy 拿不到查第 3 步的目录结构，钥匙拉不到查第 4 步的 DNS 和第 5 步的服务器配置，UID 对不上或没有加密子钥查第 2 步的导出。网站声明输入的邮箱只用于当次验证，不会存下来挪作他用。

  注意：在线工具只能证明“现在、从外网看是通的”，不能代替你自己的密钥管理。钥匙续期、加子钥、吊销之后，还是要按上面说的重新导出覆盖，再跑一遍验证。

常见问题

  • 客户端找不到密钥：先查顺序。高级方法优先，如果 openpgpkey.huanjue.me 解析到了一个没有 WKD 的服务器，客户端可能不会立刻回落到直接方法。确认子域名指向的是真正托管 WKD 的服务器，或者干脆先只做直接方法。
  • 拿到的是 HTML：SPA fallback 或 404 页面把请求吞了。检查服务器配置，/.well-known/ 必须走静态文件，不走应用路由。
  • 证书报错：WKD 只认受信任的证书链，自签名、过期、域名不匹配都会被拒绝。高级方法要给 openpgpkey.huanjue.me 单独配好证书，通配符证书也可以。
  • 哈希不对：哈希是对小写后的本地部分算的，You@huanjue.me 和 you@huanjue.me 的哈希一样，但如果本地部分本身有大写字母以外的字符，先用 gpg --with-wkd-hash 的结果为准，不要自己拼。
  • 密钥更新后别人还是拿到旧的：密钥续期、加子密钥、吊销之后都要重新导出并覆盖 hu/ 下的文件。WKD 没有自动同步，文件就是唯一来源。
  • 密钥吊销了怎么办：重新导出吊销后的公钥并覆盖原文件，让客户端拿到带吊销证书的版本；或者直接删除 hu/ 下的文件，让查询返回 404。两者都比留着旧的未吊销公钥好。
  • 只想给某一个人用，不想公开：WKD 本质上就是公开目录，只要知道哈希就能拉到文件，哈希算法也是公开的。WKD 不适合“只让特定人拿到密钥”的场景，那种需求应该直接把公钥发给对方。

安全提醒

  • 整个流程只涉及公钥。任何一步要求你导出、上传私钥的教程都是错的，立即停下。
  • 发布前用 gpg --show-keys 确认文件里没有私钥材料。
  • 不要在 WKD 目录里放其他文件，也不要开目录列表。
  • 域名和子域名的 HTTPS 配置要和主站一样认真对待，WKD 的信任基础就是域名加证书。
